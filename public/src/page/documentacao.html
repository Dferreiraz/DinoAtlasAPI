Documentação da DinoAtlas API

Tudo o que você precisa para consultar dinossauros, períodos geológicos, formações, países, museus e demais dados paleontológicos da DinoAtlas. A API é pública, somente leitura e não exige autenticação.

01 · Começando

Introdução

A DinoAtlas API é uma API REST pública e gratuita que entrega dados estruturados sobre dinossauros e o contexto paleontológico associado: períodos, épocas, formações geológicas, continentes, países, habitats, dietas, famílias, clados, classificações, descobertas e museus.

A base atual contém 100 dinossauros e mantém os registros relacionados normalizados por identificadores. Todos os endpoints públicos são GET, respondem em JSON e podem ser consumidos sem chave de API.

100 dinossauros cadastrados
36 endpoints GET públicos
15 grupos de recursos
100 requisições por 15 min
Versão em execução. O campo version de GET /api reflete a instância consultada. Neste repositório o código prepara a versão 2.5.0, que ainda não foi publicada; a última release pública é a 2.4.5. Sempre confirme a versão na resposta de GET /api.

Comece por Primeiros passos para fazer a primeira requisição ou consulte diretamente o inventário de recursos.

02 · Começando

Visão geral da API

Os recursos são agrupados por assunto. Apenas o recurso de dinossauros aceita paginação, busca, filtros e ordenação; os demais catálogos retornam a coleção completa. Formações, continentes e países também expõem uma rota para listar os dinossauros relacionados.

Somente leitura. Não existem rotas públicas para POST, PUT, PATCH ou DELETE. Como esses métodos não estão mapeados, eles recebem 404 com a mensagem "Rota não encontrada." — e não 405.

Uma requisição típica percorre quatro etapas:

1. Requisição Você envia um GET para a URL base com o caminho do recurso.
2. Validação IDs, paginação, busca, filtros e ordenação são validados antes da consulta.
3. Resposta Os dados voltam em data, com meta quando aplicável.
4. Erro Falhas retornam success: false e uma message pública.
03 · Começando

Primeiros passos

Não é necessário instalar SDK, gerar token ou configurar cabeçalhos de autenticação. Basta escolher a URL base e fazer uma requisição GET.

  1. Escolha a URL base: https://dinoapi-swg8.onrender.com/api em produção ou http://localhost:3000/api no ambiente local.
  2. Confirme que a API está no ar: consulte GET /api e verifique success: true.
  3. Faça a primeira consulta de dados: peça um dinossauro com GET /api/dinosaurs?limit=1.
  4. Leia o envelope: os registros ficam em data; a paginação fica em meta.

Requisição com cURL

cURL 
curl "https://dinoapi-swg8.onrender.com/api/dinosaurs?limit=1"

05 · Começando

Formato das respostas

Toda resposta é JSON com Content-Type: application/json; charset=utf-8. O envelope é uniforme: sucesso traz success: true e data; erro traz success: false e message.

Campo Tipo Quando aparece Descrição
successbooleanSempreIndica se a requisição foi concluída com êxito.
dataobjeto ou arraySucessoRegistro único ou coleção de registros.
metaobjetoQuando aplicávelPaginação, contagem, mensagem contextual ou ID relacionado.
messagestringErroMensagem pública e segura, em português.

Sucesso com coleção e paginação

Exemplo reduzido do envelope: a lista real traz até limit itens.

JSON · lista paginada 
{
  "success": true,
  "data": [
    {
      "id": 1,
      "name": "Tyrannosaurus Rex"
    }
  ],
  "meta": {
    "page": 1,
    "limit": 10,
    "total": 100,
    "totalPages": 10
  }
}

Sucesso com registro único

JSON · item por ID 
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Tyrannosaurus Rex",
    "scientificName": "Tyrannosaurus rex"
  }
}

Metadados possíveis

Formato de meta Onde aparece
{ page, limit, total, totalPages }Listagem de dinossauros.
{ count }Dinossauros aleatórios.
{ total }Catálogo de imagens.
{ dinosaurId, total }Imagens de um dinossauro.
{ message, count }Dinossauros por continente, país ou formação.

Erro

JSON · erro 
{
  "success": false,
  "message": "Dinossauro não encontrado."
}
Sem detalhes internos. Respostas de erro não incluem stack trace, caminhos de arquivo ou detalhes de implementação. Use o cabeçalho X-Request-Id para correlacionar uma falha com os logs do servidor.
06 · Começando

Acesso público e ausência de autenticação obrigatória

A DinoAtlas API é aberta. Nenhum endpoint exige chave de API, token, cookie ou cabeçalho Authorization. Basta enviar um GET para a URL base.

Características do acesso

  • Somente leitura: apenas métodos GET estão implementados.
  • CORS liberado: a resposta inclui Access-Control-Allow-Origin: * e permite os métodos GET e OPTIONS.
  • Sem credenciais: a API não usa cookies de sessão nem exige credentials: "include".
  • HTTPS em produção: use sempre a URL HTTPS para evitar bloqueios de conteúdo misto no navegador.
  • Dados públicos: não envie informações pessoais ou sensíveis para a API.

Cabeçalhos

Cabeçalho Obrigatório Observação
Accept: application/jsonNãoRecomendado para deixar explícito o formato esperado.
Content-TypeNãoNão há corpo de requisição nos endpoints públicos.
AuthorizationNãoNão é necessário e não altera a resposta.
CF-Connecting-IPNãoUsado internamente pelo rate limiting quando a API está atrás de Cloudflare/Render. O cliente não deve defini-lo.
Identificação para rate limiting. Em produção, a API identifica o cliente pelo cabeçalho encaminhado pela infraestrutura (CF-Connecting-IP). Em execução local, usa o IP da conexão. Você não precisa configurar nada para isso.

Exemplo de requisição mínima

cURL 
curl -H "Accept: application/json" https://dinoapi-swg8.onrender.com/api/dinosaurs/1
07 · Começando

Rate limiting

As rotas sob /api são protegidas por um limitador por cliente. A configuração padrão permite 100 requisições a cada 15 minutos. Ao ultrapassar o limite, a API responde 429 até a janela ser reaberta.

Item Valor padrão
EscopoRotas sob /api
Limite100 requisições
Janela15 minutos (900 segundos)
IdentificaçãoIP do cliente encaminhado pela infraestrutura
Fora do limite/, /docs, /health e arquivos estáticos

Cabeçalhos da resposta

Cada resposta de /api informa o estado do limitador:

Cabeçalho Significado
RateLimit-PolicyPolítica aplicada, no formato 100;w=900.
RateLimit-LimitTotal de requisições permitidas na janela.
RateLimit-RemainingRequisições restantes antes do bloqueio.
RateLimit-ResetSegundos restantes até a janela ser reaberta.
Retry-AfterPresente na resposta 429; indica quantos segundos aguardar.
X-Request-IdIdentificador único da requisição, útil em suporte e logs.

Resposta ao exceder o limite

JSON · 429 Too Many Requests 
{
  "success": false,
  "message": "Muitas requisições originadas deste IP. Por favor, tente novamente após 15 minutos."
}
Headers · exemplo de bloqueio 
HTTP/1.1 429 Too Many Requests
RateLimit-Policy: 100;w=900
RateLimit-Limit: 100
RateLimit-Remaining: 0
RateLimit-Reset: 912
Retry-After: 912
Content-Type: application/json; charset=utf-8
X-Request-Id: 2f6c1a9e-4a3f-4f0e-9c55-0b7f1d2e8a11

Boas práticas

  • Reaproveite respostas e evite repetir a mesma consulta em sequência.
  • Use paginação e filtros para reduzir o número de chamadas.
  • Ao receber 429, aguarde o valor de Retry-After antes de tentar novamente.
  • Implemente backoff exponencial em rotinas automáticas.
  • Não use o cabeçalho CF-Connecting-IP para contornar o limite; ele é controlado pela infraestrutura.

Dinossauros

5 endpoints

Recurso central da API. Retorna os 100 registros de dinossauros, com dados morfológicos, taxonômicos, geográficos e textos complementares. As rotas de listagem, busca e ID único acrescentam quatro campos de imagem ao registro.

Endpoints

GET /api/dinosaurs Lista paginada com busca, filtros e ordenação.
GET /api/dinosaurs/:id Retorna um dinossauro pelo ID, com campos de imagem.
GET /api/dinosaurs/random Sorteia um ou mais dinossauros; aceita limit de 1 a 50.
GET /api/dinosaurs/name/:name Busca por trecho do campo name, sem diferenciar maiúsculas.
GET /api/dinosaurs/:id/images Lista as imagens associadas ao dinossauro.

Parâmetros de rota

ParâmetroTipoRegraErro
:idinteiroInteiro positivo. Zeros à esquerda são aceitos (01 = 1).400 se inválido; 404 se não existir.
:nametextoTrecho do nome, até 100 caracteres, comparado sem diferenciar maiúsculas.400 se exceder 100 caracteres; 404 se não houver correspondência.

Query parameters da listagem

ParâmetroTipoPadrãoComportamento
pageinteiro ≥ 11Página desejada.
limitinteiro 1–10010Itens por página.
searchtexto ≤ 100—Busca em name, scientificName e description.
sortenum—Um dos 22 campos listados em Ordenação.
orderasc ou descascSó tem efeito quando sort é informado.
Filtros relacionaisinteiro ≥ 1—periodId, epochId, dietId, continentId, countryId, formationId, familyId, cladeId, habitatId, classificationId, museumId.
Filtros numéricosnúmero ≥ 0—lengthMin, lengthMax, weightMin, weightMax, heightMin, heightMax, estimatedSpeedMin, estimatedSpeedMax.
Combinação de filtros. Filtros relacionais, filtros numéricos e search são aplicados em conjunto com lógica AND. Consulte Filtros para os valores aceitos e exemplos.

Consumo com JavaScript

JavaScript · Fetch 
const BASE = "https://dinoapi-swg8.onrender.com/api";

async function listarDinossauros(parametros = {}) {
  const url = new URL(`${BASE}/dinosaurs`);
  Object.entries(parametros).forEach(([chave, valor]) => {
    url.searchParams.set(chave, String(valor));
  });

  const resposta = await fetch(url);
  const corpo = await resposta.json();

  if (!resposta.ok || !corpo.success) {
    throw new Error(corpo.message || `HTTP ${resposta.status}`);
  }

  return corpo;
}

const lista = await listarDinossauros({
  dietId: 1,
  periodId: 3,
  lengthMin: 10,
  sort: "weight",
  order: "desc",
  limit: 5
});

console.log(lista.meta.total);
console.log(lista.data.map((dino) => dino.name));

Paginação

Somente a listagem de dinossauros é paginada. Os demais catálogos retornam a coleção completa em data, sem meta. A paginação é aplicada depois dos filtros, da busca e da ordenação.

ParâmetroPadrãoLimiteValidação
page1Sem máximoInteiro maior ou igual a 1.
limit10100Inteiro entre 1 e 100.

O objeto meta informa:

CampoSignificado
pagePágina efetivamente retornada.
limitItens por página usados no cálculo.
totalTotal de registros após filtros e busca.
totalPagesQuantidade total de páginas.

Exemplo

cURL e JavaScript 
# cURL
curl "https://dinoapi-swg8.onrender.com/api/dinosaurs?page=2&limit=2"

url.searchParams.set("page", "2");
url.searchParams.set("limit", "2");

const resposta = await fetch(url);
const corpo = await resposta.json();
console.log(corpo.meta.page, corpo.meta.totalPages);

    { "id": 4, "name": "Brachiosaurus" }

    "page": 2,
    "limit": 2,

  }

Página fora do intervalo

Pedir uma página maior que totalPages não gera erro: a resposta é 200 com data: [] e os metadados reais.

  "data": [],

    "page": 999,
    "limit": 2,
    "total": 100,
    "totalPages": 50
  }
}

Parâmetros inválidos

RequisiçãoResposta
?page=0400 — O parâmetro 'page' deve ser um número inteiro maior ou igual a 1.
?page=1.5400 — mesma mensagem de page.
?limit=0400 — O parâmetro 'limit' deve ser um número inteiro entre 1 e 100.
?limit=101400 — mesma mensagem de limit.
?limit=abc400 — mesma mensagem de limit.
Zeros à esquerda. Parâmetros inteiros aceitam zeros à esquerda: page=02 equivale a 2 e limit=010 equivale a 10. Decimais, sinais e notação científica são rejeitados.

Filtros

A listagem de dinossauros aceita filtros relacionais e filtros numéricos de faixa. Todos podem ser combinados entre si e com search; a lógica é AND — o registro precisa satisfazer todos os critérios informados.

Filtros relacionais

Cada filtro recebe o ID inteiro positivo de um registro relacionado.

ParâmetroCampo no dinossauroExemploReferência
periodIdperiodId3Cretáceo
epochIdepochId1Cretáceo Superior
dietIddietId1Carnívoro
continentIdcontinentId2América do Sul
countryIdcountryId (array)16Brasil
formationIdformationId (array)2Formação Morrison
familyIdfamilyId1Tyrannosauridae
cladeIdcladeId1Coelurosauria
habitatIdhabitatId3Desertos e Dunas
classificationIdclassificationId1Theropoda
museumIdmuseumId1Field Museum of Natural History

Filtros numéricos

Aceitam números decimais maiores ou iguais a zero. Os limites são inclusivos: lengthMin=12 inclui exatamente 12 metros e lengthMax=13 inclui exatamente 13 metros.

ParâmetroCampoUnidadeComparação
lengthMinlengthmetroslength >= valor
lengthMaxlengthmetroslength <= valor
weightMinweightquilogramasweight >= valor
weightMaxweightquilogramasweight <= valor
heightMinheightmetrosheight >= valor
heightMaxheightmetrosheight <= valor
estimatedSpeedMinestimatedSpeedkm/hestimatedSpeed >= valor
estimatedSpeedMaxestimatedSpeedkm/hestimatedSpeed <= valor

Campos que são arrays

countryId e formationId são arrays no registro do dinossauro. O filtro correspondente encontra o registro quando o valor aparece em qualquer posição do array. Exemplo: um dinossauro com "countryId": [16, 6] corresponde tanto a countryId=16 quanto a countryId=6.

Ordenação

A listagem de dinossauros pode ser ordenada por qualquer um dos 22 campos abaixo, com sort e order. A ordenação acontece depois dos filtros e da busca, e antes da paginação.

Campos aceitos em sort
id, name, scientificName, meaning, classificationId, cladeId, familyId, periodId, epochId, dietId, habitatId, continentId, discoveryId, museumId, imageId, length, height, weight, estimatedSpeed, species, genus, status.

Regras e validação

  • order sozinho é aceito, mas não altera a ordem original.
  • sort diferencia maiúsculas de minúsculas: use exatamente os nomes listados.

  • sort com campo fora da lista retorna 400.

Como tratar

  1. Leia success antes de acessar data.
  2. Use message para exibir ou registrar o motivo, sem tentar interpretar detalhes internos.
  3. Em 400, corrija o parâmetro — não repita a mesma requisição.
  4. Em 404 de ID, confirme se o registro existe na listagem correspondente.
  5. Em 429, aguarde Retry-After e aplique backoff.
  6. Em 500, registre o X-Request-Id e tente novamente mais tarde.
JavaScript · tratamento de erros 
async function consumir(url) {
  const resposta = await fetch(url);

  if (resposta.status === 429) {
    const segundos = Number(resposta.headers.get("Retry-After")) || 60;
    throw new Error(`Limite excedido. Tente novamente em ${segundos}s.`);
  }

  const corpo = await resposta.json();

  if (!resposta.ok || !corpo.success) {
    const requestId = resposta.headers.get("X-Request-Id");
    throw new Error(`${corpo.message} (requestId: ${requestId})`);
  }

  return corpo;
}
15 · Prática

Exemplos de integração

Os exemplos abaixo usam apenas recursos nativos: fetch em JavaScript e curl no terminal. Nenhuma dependência externa é necessária.

Cliente reutilizável com Fetch

JavaScript · Fetch 
const BASE = "https://dinoapi-swg8.onrender.com/api";

async function api(caminho, parametros = {}) {
  const url = new URL(BASE + caminho);

  Object.entries(parametros).forEach(([chave, valor]) => {
    if (valor !== undefined && valor !== null && valor !== "") {
      url.searchParams.set(chave, String(valor));
    }
  });

  const resposta = await fetch(url, {
    headers: { Accept: "application/json" }
  });
  const corpo = await resposta.json();

  if (!resposta.ok || !corpo.success) {
    throw new Error(`${resposta.status}: ${corpo.message}`);
  }

  return corpo;
}

Percorrer todas as páginas

JavaScript · paginação 
async function listarTodos() {
  const nomes = [];
  let pagina = 1;
  let totalPaginas = 1;

  do {
    const resposta = await api("/dinosaurs", { page: pagina, limit: 20 });
    resposta.data.forEach((dino) => nomes.push(dino.name));
    totalPaginas = resposta.meta.totalPages;
    pagina += 1;
  } while (pagina <= totalPaginas);

  return nomes;
}

const todos = await listarTodos();
console.log(todos.length); // 100

Checklist de integração

  • Trate success e message antes de acessar data.
  • Use meta.totalPages para controlar a paginação.
  • Reaproveite os IDs de catálogos retornados pela API para montar filtros.
  • Respeite Retry-After em respostas 429.
  • Registre o X-Request-Id em falhas 500.
  • Considere o cache HTTP com ETag e If-None-Match para reduzir chamadas.
Você já pode integrar. Comece por GET /api/dinosaurs, use meta para navegar e consulte Schemas para interpretar cada campo. Em caso de dúvida sobre parâmetros, volte a Filtros, Ordenação e Paginação.
